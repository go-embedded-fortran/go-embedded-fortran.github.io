Fortran, embedded in Go.
Checked against gfortran, not against expectations.

go-embedded-fortran is in development. Its repository, fortran, is at v0.17.0, which runs go-notebook's fortran cells in one session (eval.Session; their variables stay in Fortran for now): a {{ if partial "mantra-on.html" . }}Go{{ else }}pure-Go{{ end }} front end (a parser and a semantic analyser), an evaluator that runs all 14 golden programs byte-identical to gfortran 15.2.0, an I/O runtime ported from flang-rt (71 096 of 71 135 differential cases identical, the 39 others in documented classes), an oracle harness, and a measured gate whose first figures give the verdict A first. Known limits: the evaluator's scalar loops are 8x to 108x behind gfortran -O2 (#17), the gate's browser lane is not implemented (#5), and the evaluator does not run type extension, select type, pointer components, character arrays, read from a unit or complex variables yet. It is meant to back the fortran cells of go-notebook.

A first evaluator, and honest about it.

On the gate's scalar loops, the evaluator is 8x to 108x behind gfortran -O2 (8.33 on K1, 93.31 on K2, 108.06 on K3L), an open defect (#17). The desktop ratio is at most 2 and both array kernels are within 1.2 of direct go-ndarray, but the playground home is not measured (#5), so the rule cannot pick A outright: the verdict is "A first", and it is to be re-gated after go-embedded-c M3.
